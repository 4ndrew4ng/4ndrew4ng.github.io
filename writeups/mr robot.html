The Core Story - Part 1

Cripton Server Hardening: Reconnaissance

"During my time at Cripton, I conducted a network reconnaissance and hardening project on our live domain with permission as I wanted to see if there were any vulnerabilities. I started with Whois lookups and DNS enumeration using Kali Linux CLI, then ran an aggressive Nmap scan using TCP SYN stealth and version detection. I found several vulnerable open ports, including FTP on port 21, MySQL on port 3306, and also that the website was running Apache web server on port 80. I used an aggressive scan because I needed a complete picture of our attack surface. So the complete scan includes a stealth SYN scan (-sS) to find the open ports, version detection (-sV) to identify the exact services running like which version of MySQL 5.7.32, and default scripts (-sC) to pull extra configurations like SSL certificates. This allowed me to pinpoint exactly which ports, like FTP and MySQL, needed to be locked down. So now we have like a structured map to see which holes I need to patch.

Through manual banner grabbing with curl (What software are you running?), I even discovered our WordPress version was exposed via meta tags. To validate this, I used a public source-code search engine called PublicWWW. I cross-referenced cripton.com.sg and confirmed that the exposed tag had caused the company's site to be indexed in public databases, making it an easy target for attackers.

Core Concepts

The 5 Phases of Hacking

  1. Reconnaissance: Information gathering (like checking Whois records or social media).
  2. Scanning & Enumeration: Actively probing the target to find open doors (like using Nmap to find open ports).
  3. Gaining Access: The actual exploit or attack (like brute-forcing a login or using a reverse shell).
  4. Maintaining Access: Setting up a backdoor or creating a rogue user account so the attacker can return later.
  5. Covering Tracks: Deleting logs and clearing history to hide the fact that they were ever there.
Core Concepts

Ports and Protocols

  • Port 21 (FTP): Used for file transfer. It is highly vulnerable because data is sent in plaintext, allowing attackers to read passwords by capturing packets on Wireshark.
  • Port 22 (SSH): Secure Shell. Used for secure, encrypted remote logins.
  • Port 80 (HTTP): Used for unencrypted web servers. Traffic can be easily intercepted.
  • Port 443 (HTTPS): Used for secure, encrypted web servers.
  • Port 3306 (MySQL): Used for SQL databases. It should ideally be blocked from external access via firewall rules.
  • Port 3389 (RDP): Remote Desktop Protocol. Commonly targeted by ransomware gangs.
SOC Level 1 Q&A

Core Defensive Tools

"What is a SIEM?"
It stands for Security Information and Event Management. It is a log aggregator that collects logs from firewalls, servers, and antivirus software, correlates the data, and triggers an alert if it sees a suspicious pattern.
"What is the difference between an IDS and an IPS?"
Intrusion Detection System (IDS) is like a security camera—it watches and alerts you if someone breaks in, but it doesn't stop them. An Intrusion Prevention System (IPS) is like a security guard—it watches the traffic and actively blocks malicious activity.
"What is an EDR?"
Endpoint Detection and Response. It's essentially advanced antivirus. It sits on the end-user's actual machine (the endpoint), monitors behavior, and can isolate the machine if it detects ransomware or malware.
SOC Level 1 Q&A

Security Principles

"What is the CIA Triad?"
Confidentiality (only authorized people can access the data), Integrity (the data hasn't been altered or tampered with), and Availability (the data and systems are accessible when needed).
"What is the difference between a False Positive and a False Negative?"
A False Positive is a false alarm—a system flagged something as malicious, but it's actually safe. A False Negative is a missed threat—malware got through, and the system didn't alert us. False Negatives are much more dangerous.
"What does 'Defense in Depth' mean?"
It means using multiple layers of security. If a firewall fails, you have an IDS. If the IDS fails, you have an EDR on the endpoint. You don't rely on just one defense.
SOC Level 1 Q&A

Networking Fundamentals

"Explain the TCP Three-Way Handshake."
It is how two computers establish a reliable connection. Computer A sends a SYN packet. Computer B replies with a SYN-ACK. Computer A finishes with an ACK.
"What happens when you type google.com into your browser?"
First, the computer checks its local DNS cache. If it doesn't know the IP, it queries a DNS server to resolve "google.com" into an IP address. Once the IP is found, the browser initiates a TCP handshake and requests the webpage over port 443 (HTTPS).
SOC Level 1 Q&A

Web Attacks & Vulnerabilities

"What is SQL Injection (SQLi)?"
It's when an attacker enters malicious SQL commands into a website's input field (like a login box) to manipulate the backend database. You prevent it by using prepared statements and sanitizing inputs.
"What is Cross-Site Scripting (XSS)?"
When an attacker injects malicious JavaScript into a legitimate webpage. When other users visit that page, the script executes in their browser, potentially stealing their session cookies.
"What is a DDoS attack?"
Distributed Denial of Service. It's when an attacker uses a botnet (thousands of infected computers) to flood a target server with overwhelming traffic, causing the server to crash or become unavailable.
SOC Level 1 Q&A

Cryptography Basics

"What is the difference between Symmetric and Asymmetric encryption?"
Symmetric encryption uses the exact same key to both encrypt and decrypt data (it's fast, but securely sharing the key is hard). Asymmetric encryption uses a public key to encrypt the data, and a private key to decrypt it (slower, but much safer).
"What is a Hash?"
A hash is a one-way mathematical function that turns data into a fixed-length string of characters. You can't reverse a hash to get the original file back. It's mainly used to verify file integrity (making sure a file wasn't tampered with) or to safely store passwords.
SOC Level 1 Q&A

Incident Triage Scenarios

"You see an alert for a successful login from a foreign IP address. What do you do?"
First, verify if it is a true positive. Check if the user is traveling or using a VPN. If it is illegitimate, lock the account, force a password reset, and check the logs to see what the attacker accessed. Finally, escalate the ticket.
"An employee reports a phishing email. How do you analyze it?"
Do not click the links. Check the sender's actual email address. Inspect the email headers for the true origin IP. Hover over links to see the actual destination URL, or run the URL through a sandbox like VirusTotal. If it has an attachment, analyze the hash.
"An endpoint triggers a ransomware alert. What is your very first step?"
Immediately isolate the host from the network. Disconnect the ethernet or disable the network adapter to prevent the ransomware from moving laterally to other machines. Do not reboot or power down the machine right away, as that destroys volatile memory needed for investigation. Escalate to Level 2.
