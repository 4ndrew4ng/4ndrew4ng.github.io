Case Study: Web Server Reconnaissance & Hardening

Project Overview

Target: [Cripton.com.sg] ([redacted-domain.com]).

Objective: I conducted a comprehensive network reconnaissance and vulnerability assessment on a live web server to identify and patch critical security flaws. Initial scans revealed the server was exposing critical infrastructure details, transmitting credentials insecurely, and leaking sensitive CMS version data.

Phase 1: Intelligence Gathering & OSINT

The engagement began with passive reconnaissance to map the organization's public footprint.

  • A Whois lookup revealed the domain's registration details, including a direct technical contact email.
  • The Problem: This exposed information provides a direct avenue for attackers to execute spear-phishing campaigns, such as masquerading as the domain registrar to send malicious links.
  • The Solution: Mitigated this risk by recommending the purchase of "Whois Privacy Protection" from the registrar to redact personal names and emails from the public.

Phase 2: Network Scanning & Enumeration

Using tools like dnsrecon and Nmap, I mapped the server's infrastructure and identified active services.

  • DNS enumeration identified the root domain IP address and the mail subdomain.
  • Aggressive Nmap scans utilizing TCP SYN stealth (-sS), version detection (-sV), and default scripts (-sC) revealed multiple open ports: Port 21 (FTP), Port 80/443 (HTTP/HTTPS), and Port 3306 (MySQL).

Critical Vulnerabilities Discovered:

1. Insecure File Transfer (Port 21): Attackers on the same network could capture packets using Wireshark to read passwords in clear text. Additionally, the open port was vulnerable to brute-force attacks using tools like Hydra.
2. Database Exposure (Port 3306): The exposed MySQL port created a vector for Denial of Service (DoS) attacks using custom scripts or Hping3.
3. Direct IP Targeting: By resolving the direct IP address, attackers could bypass cloud provider protections to launch direct attacks.

Phase 3: Web Application & CMS Vulnerabilities

While the initial Nmap scan successfully identified the web server, the specific version was masked via Security by Obscurity.

  • I performed manual banner grabbing using the curl -I command, exposing a CMS redirect header.
  • Inspection of the HTML source code revealed a meta name="generator" tag that explicitly disclosed the exact CMS version running on the site.
  • Real-World Impact: Cross-referencing this data with public source-code search engines confirmed the domain was already indexed in targetable databases specifically due to this exposed generator tag. Attackers seeking vulnerabilities for that specific CMS version could locate the target instantly without active scanning.

Phase 4: Hardening & Remediation Implementation

To neutralize these attack vectors and secure the server infrastructure, I implemented the following hardening measures:

Protocol Migration: Migrated the insecure FTP service to encrypted FTPS/SFTP. This implementation utilizes strong encryption, ensuring passwords and data cannot be stolen via packet sniffing.
Firewall Configuration: Configured strict WAF (Web Application Firewall) and server rules to block User Enumeration scans and prevent all external connections to the database port, mitigating DoS risks. Additionally, configured the server's firewall to only accept traffic originating from the cloud provider.
Transport & Access Security: Enabled HSTS (HTTP Strict Transport Security) to force browsers to never attempt unencrypted connections again. Implemented rate-limiting and login lockdown policies to neutralize Hydra-style brute force attacks.
Attack Surface Reduction: Cleaned up the DNS configuration by deleting unused A records and subdomains to minimize the available attack surface.
